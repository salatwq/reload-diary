# My School Reload — заметки для Claude

Android-приложение (Kotlin + Jetpack Compose) — личный школьный дневник для «Моей школы» на Госуслугах
(Оренбургская область) в стиле синего меню паузы из Persona 3 Reload. Делается для одного человека (владелец репозитория).
Автор в приложении: t.me/salatwq (туда же пишут о багах).

## Как работать с владельцем
- Общаться по-русски, коротко, без лишней воды.
- Владелец работает только с телефона и не умеет собирать приложение: любой результат — это **ссылка на APK**.
- Из среды Claude недоступны ни Maven/Google, ни сайт Госуслуг (только российские IP) → локально проект **не собрать и не запустить**,
  API не проверить. Всё проверяется только на телефоне владельца. Честно говорить, что изменение не проверено на устройстве.
- Запросы/ответы API владелец присылает сам через кнопку «ПОДЕЛИТЬСЯ ЗАПРОСАМИ» во встроенном браузере (Аккаунт → Войти → МОЯ ШКОЛА).
  Просить только структуру данных, личные данные (ФИО, СНИЛС, ИНН, паспорт, телефон, адрес, почта) не просить, не сохранять и
  не повторять; если они пришли — предупредить владельца и не использовать.

## Сборка и выдача
- Любой push в `main` запускает `.github/workflows/build.yml` → `gradle assembleDebug` → релиз `build-<run_number>` с `app-debug.apk`.
- Ссылка: `https://github.com/salatwq/reload-diary/releases/download/build-N/app-debug.apk`, где N — `run_number` последнего успешного запуска
  (`curl https://api.github.com/repos/salatwq/reload-diary/actions/runs`, затем `.../releases/tags/build-N`).
- Если сборка упала: шаг «Save log» пушит ветку `buildlog`; ошибки компилятора: `git fetch origin buildlog && git show FETCH_HEAD:build.log | grep "^e: "`.
- `app/debug.keystore` (пароль `android`) закоммичен намеренно: фиксированная подпись нужна, чтобы новые версии ставились поверх старых.
  Менять нельзя — владельцу придётся удалять приложение.
- В коммитах — трейлеры `Co-Authored-By` и `Claude-Session`, как требует среда.

## Как устроены данные («Моя школа»)
- Хост `https://www.gosuslugi.ru`, API `/api/myschool/`. Запросы делает **сам телефон** из скрытого WebView (`data/GosuApi.kt`), cookies входа подставляются
  автоматически. Никаких серверов-посредников нет и быть не должно.
- `GET /v2/auth/student?role=student` → список учеников, нужен `student_id`.
- `POST /v1/datamart`, тело — массив `{interval_id, obj_type, student_id}`. Ответ — массив `{interval_id, obj_type, data_status, data:[…]}`.
  - `interval_id` недельных данных = **номер ISO-недели + учебный год**: `432026` — 43-я неделя, учебный год 2026/27. Для января–августа неизвестно,
    какой суффикс (учебный или календарный год) — `Plan.kt` запрашивает оба.
  - Типы: `student_marks` (оценки), `student_lessons` (уроки: `start_datetime`, `end_datetime`, `subject_name`, `active`, учитель), `student_homeworks_materials`
    (ДЗ: `description`, `plan_ready_date` — срок, `issue_date`), `student_events`, `student_classes` (интервал = год, например `2026`).
  - Ответ `202` = «данные готовятся» — повторять запрос (так делает и сам сайт); также повторяем 429/5xx.
  - В ответе по оценкам лежат и оценки одноклассников (`students_test`) — в JS отбрасываются, в кэш попадают только нужные поля.
- Итоговые оценки (четверти/полугодия/год): **настоящий формат пока не известен** (запрос не получен). `Builder.isFinal` угадывает по тексту типа работы.

## Архитектура
- `data/Plan.kt` — что запрашивать (оценки с 1 сентября; уроки и ДЗ на 5 недель назад и 6 вперёд). `data/GosuApi.kt` — выполнение в WebView
  (3 запроса параллельно, повторы, дедлайн 52 с). `data/Cache.kt` — локальный кэш ответов по ключу «интервал|тип» (пустой ответ не затирает непустой).
  `data/Builder.kt` — кэш → `DiaryData`. `data/Sync.kt` — всё вместе; при любой ошибке остаются сохранённые данные.
- `data/Session.kt` — копия cookies Госуслуг: сеансовые cookies WebView теряет при перезапуске, поэтому они сохраняются в приватных настройках и при старте
  процесса возвращаются (только те, которых в браузере нет) с продлённым сроком. Живость сессии на стороне Госуслуг от этого не зависит;
  фоновая проверка раз в ~15 мин (`work/MarksWorker.kt`) заодно поддерживает сессию.
- `work/MarksWorker.kt` — уведомления о новых оценках (`known_marks` в SharedPreferences; оценки старше 7 дней не объявляются).
- `ui/` — Compose-экраны: меню (Расписание, Домашка, Оценки, Путь медали, Аккаунт), `WeekBar.kt` (выбор дня + стрелки недель −5…+5, общие для расписания и ДЗ),
  `Components.kt` (палитра `P3`, наклонные формы, анимированный фон), `Wipe.kt` (заставка и «шторка» между экранами), `BrowserScreen.kt` (вход через Госуслуги).
- Полугодия сбрасываются 1 июля: июль–декабрь — 1-е (оценки с 1 сентября), январь–июнь — 2-е (с 1 января). «Путь медали»: сколько пятёрок нужно до среднего 4,60.

## Правила дизайна
- Стиль в духе Persona 3 Reload, но **оригинальная графика**: ассеты игры (защищённые авторским правом) не использовать, даже если владелец разрешает.
  Логотип `res/drawable-nodpi/logo.png` принадлежит владельцу — его использовать можно.
- В списках (`LazyColumn`) не делать анимацию появления: при быстрой прокрутке карточки оставались невидимыми. Анимация осталась только у пунктов меню.

## Грабли, на которые уже наступали
- Свойство `demo` и функция `setDemo` дают конфликт JVM-сигнатур — функция называется `switchDemo`.
- Для скрытого WebView откладывать действия через `Handler(Looper.getMainLooper())`, а не `view.post` (у неприсоединённого view не выполняется).
- В Kotlin raw-строках с JS нельзя использовать `$` (шаблоны) — писать JS без `$` и без template literals.
- Параллельные обновления (двойной запуск) и полная замена данных при частичном сбое приводили к пропаже оценок/расписания — поэтому есть защита `loading`, кэш и слияние.

## Что открыто
- Итоговые оценки: ждём запрос от владельца (раздел «Итоговые» в «Моей школе» → «ПОДЕЛИТЬСЯ ЗАПРОСАМИ»).
- Пока неизвестно, как долго живёт сессия Госуслуг; если вход слетает — смотреть строку «Вход сохранён…» в Аккаунте.
